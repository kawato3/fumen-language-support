# Fumen Language Support

[English](README.md) | 日本語

[hbjpn/fumen](https://github.com/hbjpn/fumen/) の記法で `.fumen` ファイルを書くための、軽量な VS Code 拡張です。標準は英語、VS Code の表示言語が日本語のときは日本語のメニュー・説明・操作ガイドを使います。

チートシートと操作ガイドの先頭にも、英語・日本語を切り替えるリンクがあります。

設定・記号・ひな形の入力を支援し、編集しながら楽譜を横にプレビューできます。空白だけの簡易整形にも対応します。コード名の補完、コード進行や拍数の判定は行いません。

![左に構文を色分けした Fumen の編集画面、右に楽譜プレビューを表示](media/screenshots/editor-preview.jpg)

英語表示での使用例です。画像の [英語サンプル](examples/notation-en.fumen)のほか、[日本語サンプル](examples/notation.fumen)も用意しています。

## まず使ってみる

必要なのは VS Code 1.90 以降だけです。拡張を使うために Node.js や Fumen 本体をインストールする必要はありません。

以前のローカル版 `fumen-local.fumen-language-support` を使っている場合は、先にアンインストールしてから `kawato3.fumen-language-support` を導入してください。二重に動くことを防ぐためです。`.fumen` ファイルには影響しません。

1. VS Code の左側にある「拡張機能」を開きます（macOS: `⌘⇧X`、Windows/Linux: `Ctrl+Shift+X`）。
2. 検索欄に `@id:kawato3.fumen-language-support` と入力します。
3. 発行者が **Katsushi Kawato** の **Fumen Language Support** を選び、「インストール」を押します。
4. 再読み込みの案内が出たら、未保存の変更を保存してから実行します。
5. コマンドパレット（macOS: `⌘⇧P`、Windows/Linux: `Ctrl+Shift+P`）を開き、`Fumen: 新しい譜面を作成` を選びます。
6. 曲名を入力して Tab を押すと、次の記入箇所に移ります。最後に `.fumen` の拡張子で保存します。

ローカル版を使う場合は、拡張機能パネルの `…` →「VSIX からのインストール…」で `fumen-language-support-1.0.1.vsix` を指定します。1.0.0 はアンインストールせず、そのまま更新できます。自分で作成する手順は、後述の「開発・パッケージ作成」を参照してください。

既存の `.fumen` ファイルを開いても自動で有効になります。ウィンドウ右下の言語表示が `Fumen` なら認識されています。

導入後はコマンドパレットの `Fumen: 使い方を開く` から、オフラインの操作ガイドを開けます。

## 機能

| 機能 | 動作 |
| --- | --- |
| 色分け | 設定、コード、小節線、構成記号、音価、注記、歌詞を区別。VS Code のカラーテーマに従います。 |
| 括弧・引用符 | `[]`、`()`、ダブルクオート、シングルクオート、バッククオートの自動補完。 |
| 設定名の補完 | `%` を入力すると `TITLE`、`ARTIST`、`SHOW_STAFF` などを提案。 |
| 設定値の補完 | `SHOW_STAFF`、`SHOW_FOOTER`、`KEY_TYPE` の値を提案。 |
| 記号の補完 | 小節内の `<` で `<D.S.>` などを提案。コード・休符などの `:` で音価を提案。 |
| スニペット | 曲のひな形、4小節、8小節、セクション、繰り返し、1番・2番括弧、注記、歌詞。 |
| ホバー | 設定や記号にマウスを重ねると、表示言語に合わせた短い説明とチートシートを開くリンクを表示。チートシート内から公式資料も開けます。 |
| 基本チェック | 設定の代入形式・JSON 値・既知の設定の型と選択肢、括弧や引用符の閉じ忘れを表示。 |
| 楽譜プレビュー | Fumen 1.3.3 をもとにしたレンダラーを同梱。保存前の編集も反映し、複数ページ、拡大・縮小、幅に合わせる表示に対応。 |
| コード構成要素の表示 | 同梱レンダラーだけの独自機能。本家のコンパクトな配置を保つか、`Am7`・`AM7` のような通常サイズ・同じ基準線の表記にするかを選べます。詳しくは[チートシート](docs/CHEATSHEET.ja.md)の独立した節を参照してください。 |
| チートシート | 記法・記述例を英語・日本語でまとめたオフラインの一覧。本のボタンから横に開けます。 |
| 簡易整形 | VS Code 標準の「ドキュメントのフォーマット」で、譜面の構造や内容を変えずに空白を整理。 |
| 印刷・PDF 保存 | Chrome の印刷用ページでベクター描画を保持。拡張に PDF 生成ライブラリーは追加しません。 |

例えば `%TI` から `TITLE` を選ぶと `%TITLE=""` が入り、引用符の間にカーソルが移ります。既存の値を補完するときは、引用符が重複しないように置き換えます。

## 入力を邪魔しない設定

`.fumen` では本文の単語を拾う候補表示と、一般的な文字入力中の自動候補表示を既定でオフにします。`%`、`=`、小節内の `<` や `:` などで文脈に合う候補を出します。候補は Escape で閉じられます。

手動で候補を出すには「候補をトリガー」コマンドを使えます。通常は `Ctrl+Space` です。macOS で入力ソース切り替えと衝突する場合は、コマンドパレットから実行できます。

スニペットは `Fumen: ひな形を挿入` から選ぶのが簡単です。`fumen-4bars` などの接頭辞を入力してから手動で候補を呼び出すこともできます。小節やセクションのひな形は行頭、注記や歌詞は小節内に挿入します。

これらは Fumen 用の既定値で、ほかの言語には影響しません。ユーザー自身の設定やほかの拡張の候補表示は優先されることがあります。

## 設定

VS Code の「設定」で `Fumen` を検索します。

| 設定 | 既定値 | 内容 |
| --- | --- | --- |
| `fumen.diagnostics.enabled` | `true` | 基本チェックを有効にする。 |
| `fumen.diagnostics.delay` | `700` | 入力停止後、診断を更新するまでのミリ秒数。保存時は直ちに更新。 |
| `fumen.print.chromePath` | 空文字列 | Chrome 実行ファイルの絶対パス。通常は標準の場所を自動検出。ユーザー設定だけが有効。 |

## 編集しながら楽譜を見る

`.fumen` を開き、エディター右上のプレビューボタン、またはコマンドパレットの `Fumen: 横にプレビューを開く` を使います。左で編集し、右で結果を確認できます。保存は不要で、入力が止まって約0.3秒後に更新します。閉じている間は描画しません。

プレビューは1つで、開いた文書に固定されます。ほかの曲を表示したいときは、その文書で同じコマンドを実行します。元の文書を閉じた場合や、保存・名前変更で元の文書が置き換わった場合は、プレビューを開き直してください。

入力途中で解析・描画できなくなった場合は、同じ文書の最後の正常な表示を残し、上部に理由を表示します。修正すると自動復帰します。これは最新の入力が描画できている状態とは異なります。文書を空にした場合や別の文書に切り替えた場合には古い楽譜を消します。

既定は本家の A4 設定です。`%PARAM` の指定を優先し、表示倍率を変えても記述や用紙内の配置は変えません。楽譜は白い用紙で表示し、操作部分は VS Code のテーマに従います。「＋」「−」「幅に合わせる」で見やすい大きさにできます。更新時はスクロール位置をなるべく維持します。

同梱レンダラーは Fumen 1.3.3 をもとにしており、コード構成要素の表示についてだけ、`minor_label`、`major_label`、`chord_suffix_style` という独自の追加項目があります。短調・長調の記号と、本家のコンパクトな配置または全構成要素を通常サイズ・同じ基準線にする配置を選べます。これらは公開済みの Fumen 1.3.3 のパラメーターではなく、ほかの Fumen ツールでは無視されることがあります。見た目の違い、既定値、共有時の注意は、[チートシートの「拡張固有のコード構成要素表示」](docs/CHEATSHEET.ja.md#extension-chord-display)を参照してください。

## VS Code 以外でレンダラーパッチを使う

Fumen 1.3.3 を使う別のアプリケーション向けには、対応するソースパッチ、適用手順、実例を [Fumen 1.3.3 コード構成要素表示パッチ](https://github.com/kawato3/fumen-language-support/tree/main/patches/fumen-1.3.3-chord-component-display)にまとめています。これは開発者向けのソース配布物であり、VSIX には含めません。指定した上流コミットにだけ適用し、Fumen 本家の正式機能ではなく独自に保守する追加機能として扱ってください。

プレビューは10万文字・100ページ・1回の描画につきページ画像の合計3,200万画素までです。文字計測用のキャッシュには別途1,600万画素の上限があります。`%PARAM` の text_size や pixel_ratio を繰り返し変更してキャッシュが上限に達した場合は、プレビューを閉じて開き直してください。極端な用紙寸法や文字サイズなどもエラーにします。これらは画像確保の制限であり、プロセス全体のメモリー量や描画時間、上限内のすべての記述の描画を保証するものではありません。

プレビューは読み取り専用です。楽譜上の直接編集、楽譜から元の小節への移動、左右のスクロール同期はありません。スクリーンリーダーでは元のテキストを使用してください。

## 印刷・PDF に保存する

この機能には **Google Chrome** と **ローカルのデスクトップ版 VS Code** が必要です。Chrome は印刷時だけ必要で、拡張には同梱しません。Remote SSH・WSL・コンテナー・ブラウザー版 VS Code からの印刷には対応していません。

1. コマンドパレットまたは本文の右クリックメニューで `Fumen: Chrome で印刷用ページを開く` を選びます。正常に描画できているプレビューの「印刷 / PDF」からも開けます。
2. Chrome で描画が完了したら「印刷 / PDF に保存」を押します。
3. Chrome の印刷先を「PDF に保存」、用紙を A4、余白を「なし」にし、ヘッダーとフッターをオフにします。保存先は自分で選べます。

印刷用ページは、未保存の編集も含めた、その時点の譜面のコピーです。その後の編集は追従しないため、修正したら VS Code から開き直してください。不正な記述では古いプレビュー画像を代用しません。独自の用紙寸法は、縦横比を保って A4 内に収めます。

Fumen の Canvas 描画命令を記録し、Chrome の印刷時に同期的に再実行します。Chrome と使用フォントが対応する部分はベクター描画・検索可能な文字として残ります。SVG 変換や、画像への見えない文字の重ね合わせは行いません。文字検索やフォントの結果には OS・Chrome の版による違いがあり得ます。短い譜面ではフォントの埋め込みにより画像方式より容量が増える場合があります。通常の描画制限に加え、印刷用の描画命令数にも上限を設けています。

Chrome を標準以外の場所に入れている場合は、ユーザー設定の `fumen.print.chromePath` に実行ファイルの絶対パスを指定します。起動引数とワークスペース設定は受け付けません。印刷の既定ショートカットはなく、「キーボード ショートカット」で好きなキーを割り当てられます。

## 記法をすぐに調べる

エディター右上の本のボタン、または `Fumen: チートシートを開く` で、記法一覧を横に表示します。表示言語が日本語なら日本語版、それ以外なら英語版を選びます。先頭のリンクで手動切り替えもできます。Fumen 1.3.3 に合わせた記述例を同梱しているため、ネット接続は不要です。詳しく知りたいときは一覧内の公式資料へのリンクを使えます。公式サイトへのリンクを開く場合のみ、ネット接続が必要です。

チートシートは標準の Markdown プレビューを使い、表示対象を固定します。繰り返し実行すると既存のタブを開きます。既に右側に楽譜プレビューがある場合は、同じグループの別タブになります。標準の Markdown サポートを無効にしている場合は有効にしてください。開けないときの案内から公式チートシートをブラウザーで開くこともできます。

「使い方」は拡張の操作説明、「チートシート」は Fumen の記法一覧です。

`.fumen` の本文を右クリックしても、「横にプレビューを開く」「チートシートを開く」を選べます。

## 空白を整形する

本文の右クリックメニュー、またはコマンドパレットから、VS Code 標準の「ドキュメントのフォーマット」を実行します。既定キーは macOS が **Shift+Option+F**、Windows が **Shift+Alt+F**、Linux が **Ctrl+Shift+I** です。こちらは同時に押します。

小節線の前後に空白を入れ、記号間の連続した半角空白・タブを1つの空白に揃え、行末の空白を除きます。設定の代入は `%NAME=value` に揃えます。連続する空行は1行にまとめ、単独の空行は残します。ただし、文字列・ラベルの内部と、行継続記号 `\` の直後の空行は、譜面への影響を避けるため維持します。そのほかの改行、改行形式、インデント、コード表記、歌詞・注記・ラベルの内部、JSON 設定値の内容は変更しません。小節線の縦揃えと選択範囲だけの整形は対象外です。

通常の「元に戻す」1回で整形全体を戻せます。引用符などが閉じていない文書と50万文字を超える文書では整形を省略し、不正な JSON の設定行はそのまま残します。

拡張側で保存時の自動整形や既定のフォーマッターを設定することはありません。利用者が既に **Editor: Format On Save** を有効にしていれば、Fumen にも適用されます。複数のフォーマッターがある場合は「ドキュメントのフォーマット方法…」から既定のフォーマッターを選べます。[VS Code 公式の整形機能の説明](https://code.visualstudio.com/docs/editing/codebasics#_formatting)も参照してください。

## キーボードショートカット

横にプレビューを開く操作には、Markdown／AsciiDoc の慣例に合わせた既定キーを用意しています。

- macOS: **⌘K を押して離し、V** を押す。
- Windows/Linux: **Ctrl+K を押して離し、V** を押す。

Fumen のテキスト編集欄にフォーカスがある場合だけ有効です。ほかの言語やターミナルの操作には割り込みません。同じ場所に利用者のキー設定がある場合は、その設定が優先されます。

チートシートやひな形など、ほかのコマンドには既定キーを割り当てていません。利用者は VS Code の「キーボード ショートカット」で `Fumen` を検索し、好きなキーを追加・変更できます。詳しい操作手順は `Fumen: 使い方を開く` にあります。この拡張が利用者の `keybindings.json` を書き換えることはありません。

## チェックの範囲

この初版のチェックは軽量な記法チェックです。Fumen 本体による完全な解析・描画確認の代わりにはなりません。小節線の不足、未知の演奏記号、コード表記、拍数の合計、繰り返し先の対応などは検証しません。「問題」がなくても描画できる保証はありません。

拡張独自の設定や将来追加される設定を妨げないように、未知の `%名前` はエラーにせず、値が JSON として成立するかだけ確認します。`SHOW_STAFF` と `KEY_TYPE` の `AUTO` は上流実装で使われている値として扱います。

50万文字を超える文書では基本チェック・動的補完・ホバーを省略し、「問題」にその旨を表示します。色分けとスニペットは利用できます。診断は1ファイルあたり最大100件です。

改行・空行は譜面の配置に関わるため、整形時も配置に影響する区切りを維持します。`<` には左揃えやシンコペーションの意味もあるため、`>` は一律に自動挿入せず、演奏記号の補完時に挿入します。Fumen の注記は譜面に表示するテキストなので、汎用のコメントアウト記法は追加していません。

アウトラインと折り畳みは実装していません。

## 開発・パッケージ作成

開発には Node.js 22 以降と npm を使います。

```sh
npm ci
npm run check
npm run test:integration
npm run test:print
npm run package
```

`npm run package` はテストとビルドを実行し、プロジェクト直下に VSIX を生成します。Marketplace への公開や npm への公開は行いません。VS Code の F5 キーでも、開発用の別ウィンドウで試せます。

詳細は [開発ガイド](docs/DEVELOPMENT.md) と [公開ガイド](docs/PUBLISHING.md) を参照してください。登録済みの発行者 ID は `kawato3`、拡張 ID は `kawato3.fumen-language-support` です。

## データの扱い

描画はローカルで完結し、拡張による譜面の送信、アカウント登録、テレメトリーはありません。ホバーの公式資料リンクを自分で開く場合はブラウザーがウェブサイトへアクセスします。印刷時だけ Chrome をシェルを介さず起動します。プレビューと印刷用ページは同梱の Fumen 本体を使い、外部サイトのスクリプトは読み込みません。

印刷時には原稿と第三者ライセンスを含む非公開の一時 HTML ファイルを、拡張用の VS Code 保存領域に作成します。拡張の終了時に削除し、異常終了で残った24時間以上前のファイルは次の印刷操作時に削除します。VS Code を閉じる前に PDF を保存してください。利用者の Chrome の拡張機能・設定や、選択する印刷先は、この拡張では制御しません。

非表示から戻ったときの復元用に、表示倍率・スクロール位置・直前の正常な譜面テキストを VS Code の Webview 状態に保持します。プレビューを閉じると、この状態は破棄されます。

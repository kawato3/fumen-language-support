## 基準と範囲

利用者が合意した要件を基準にした。

- 音楽的な判断やコード名の提案を増やさず、設定・記号・ひな形の入力を支援する。
- 未保存文書をローカルでプレビューし、不完全な入力でも編集内容を変えない。正常表示の保持、修正後の復帰、別文書への切り替えを正しく扱う。
- 英語を既定とし、日本語の VS Code では日本語を提供する。ヘルプはオフラインで開き、相互リンクで言語を切り替えられる。
- 未信頼の文書を実行コードとして扱わず、過大な描画を制限する。同梱物のライセンス・帰属表示を保持する。
- 小規模な拡張として理解しやすく保つ。Fumen の詳細な彫版品質、音楽的妥当性、PDF 出力、楽譜上の編集は対象外。

主レビューでは言語支援、コマンド、設定・多言語対応、テスト、ビルド・配布、ライセンスを確認した。厳格レビューとして独立担当による安全性・状態管理・非同期処理の検証を1回追加し、指摘を統合した。修正後は累積差分から影響を追い、同じ要件で検証した。

## 修正した重要な問題

### P1: 補完で後続の譜面内容を消す可能性

責任箇所: `src/language.ts:52`、修正した範囲判定は同ファイル57行目。

`| <D¦ C | <Fine> |` の `¦` をカーソル位置として `<D.S.>` を補完すると、従来は `| <D.S.> |` になった。字句読み取りが後ろの `<Fine>` の `>` を閉じ記号と見なし、補完側がその全範囲を置換していた。後続の小節・注記を保持する契約への違反である。改行後の配置記号にまで範囲が伸びる例もあった。

補完側だけを修正し、単独の記号として閉じているときだけ全体を置換するようにした。それ以外は入力済みの接頭辞だけを置換する。Fumen の解析・音楽的判定は追加していない。

回帰証拠:

- `test/unit/language.test.ts` の新規ケースが、修正前に期待文字列との不一致で失敗した。小節・次行の配置記号・注記・歌詞内の `>` と、通常の閉じ記号を検証する。
- 修正後は言語支援の全単体テストが成功した。
- `test/integration/editing.test.ts` では実際の補完プロバイダーが返す置換範囲を適用し、後続の小節と `<Fine>` が残ることを確認した。

### P1: Fumen 内部の文字計測キャッシュがページ画像の予算を迂回する

責任箇所: `src/webview/main.ts:87`、新しい限定的な保護処理は `src/webview/measurement-budget.ts:15`。

従来の `CanvasBudget` は、拡張が提供するページ Canvas のみを対象にしていた。しかし Fumen 1.3.3 は、グローバルな pixel_ratio と text_size の組み合わせごとに文字計測用 Canvas を保持する。`text_size=4`、`pixel_ratio=3` は従来の個別上限内だが、内部では7200×7200画素、RGBA 換算で約207 MBとなる。異なる組み合わせへの編集でさらに蓄積する。

上流の根拠は `media/vendor/fumen.js:16634`、16908行目、17092行目付近。独立担当の小さなブラウザー試験でも、異なる2組の設定で別々の計測 Canvas が作られることを確認した。

保護処理は解析後・描画前に実効値を解決し、Webview の存続期間を通じて、文字計測 Canvas を合計1,600万画素まで予約する。同じ組み合わせは重複計上せず、過大な単一確保・累積確保を止める。`pixel_ratio=null` の自動密度にも上限を適用する。予約は上流のキャッシュと同じ寿命を持ち、描画失敗時も解放しない。

設定値を書き換える方法は採用せず、上流ファイルも変更していない。毎回レンダラーを作り直すだけではモジュール全体のキャッシュは消えないため、37行の独立した保護処理を追加した。全文書のレイアウト計算を独自実装するものではない。

回帰証拠:

- `test/unit/measurement-budget.test.ts`: 単一確保、累積、重複、自動密度、拒否後の通常編集、新しい Webview の予算を検証。保護処理のない段階では期待した拒否が起きず失敗した。
- `test/integration/preview.test.ts`: 実際に複数の設定で描画し、上限到達時のエラーと正常画像の保持を確認。修正前は上限を超えて描画が成功し、期待したエラー待ちが失敗した。修正後は成功した。
- 以前の設定への復帰と、閉じて開き直した後のキャッシュ解放も確認した。

## テストと構成の整理

統合テストは編集・プレビュー・ヘルプの名前付き13ケースに分割した。各ケースの文書・表示・登録を片付け、変更した設定は `finally` で復元する。描画の待機では文書 URI とリビジョンを確認する。以前の成功を次の編集の成功として採用しない。

通常は状態の成立を待ち、非表示中の更新禁止などの負の非同期契約だけは、デバウンス時間を含む明示的な観測期間で確認する。失敗ケースは名前と原因を報告し、終了コードも失敗になる。片付けに失敗した場合は後続を止める。

既存の検証内容は維持した。資料内の例・目次・翻訳キーの個数を固定したアサートは、必要な内容が存在し、リンク先・表の列・翻訳引数が正しいことの検証へ整理した。ソース全体に日本語がないことを求める検査は外し、翻訳キーと実際の表示言語の検証を維持した。新しい依存パッケージは追加していない。

同梱例の描画成功は、拡張が配るコピー用の例の品質を保証するために残した。詳細なピクセル比較や Fumen 自体の音楽的な正しさの検査は追加していない。

## VS Code の慣習・安全性

次の既存の構成は維持してよいと判断した。

- 宣言的な言語・スニペット・メニュー・文脈限定キー割り当て。独自 Language Server や整形処理は不要。
- `package.nls*.json` と `vscode.l10n`、`vscode.env.language` に基づく表示。ユーザーのキー割り当て・表示言語を変更しない。
- ヘルプは標準 Markdown 表示、楽譜だけを Webview で表示。
- 最小のローカル参照範囲、CSP、HTML への原稿埋め込み禁止、メッセージの型・URI・リビジョン検査。
- `retainContextWhenHidden` を使わず、Webview の標準状態保存と破棄処理を利用する。
- VSIX は許可リストで作成し、実行時の外部ライブラリー取得・アカウント・テレメトリーは追加しない。
